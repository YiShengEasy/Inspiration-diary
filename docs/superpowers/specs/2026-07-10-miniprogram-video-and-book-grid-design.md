# 小程序视频播放与灵感册三列布局设计

## 目标

- 普通视频类型灵感卡片可在详情页直接播放，并支持保存视频到手机相册。
- “我的 > 灵感册”使用固定三列网格，每项只展示封面、名称和灵感数量。
- 保持现有后端接口、鉴权方式和其他卡片类型行为不变。

## 视频卡片数据流

卡片详情继续通过 `GET /api/db/cards/:id` 获取数据。接口已返回 `videoAssets`，小程序在标准化卡片时解析视频资源地址，并将视频卡的第一个资源作为主视频。

受保护的视频地址不能依赖播放器直接携带登录请求头。详情加载时复用现有 `downloadAsset` 流程，将主视频和可用封面下载为本地临时路径，再把临时路径交给小程序 `<video>` 组件。下载失败时保留原地址作为降级路径，并在播放器没有有效资源时显示“暂无可播放视频”。

## 详情页表现

- `type === "video"` 时，详情顶部显示固定 16:9 的视频播放器。
- 播放器开启原生控制条，使用 `object-fit="contain"`，背景为黑色。
- 视频卡类型标签显示“视频”，标题优先使用视频原文件名，其次使用标签或默认名称。
- 底部下载按钮对视频卡调用保存视频逻辑；图片卡仍保存图片，文档卡保持现有不可下载图片提示。
- 组合卡继续使用现有生成记录播放器，不改变其数据结构和交互。

## 灵感册三列布局

“我的 > 灵感册”从横向列表改为固定三列网格。每个格子包含：

- 1:1 方形封面；没有封面时显示统一占位。
- 最多两行的灵感册名称。
- 一行灵感数量。

描述文字不在三列卡片中显示。点击区域覆盖整个格子，仍进入对应真实灵感册。空状态横跨三列。

## 错误处理

- 卡片接口失败时沿用当前详情错误状态。
- 视频资源为空时不渲染空播放器，改为显示明确提示。
- 视频保存失败时提示检查相册权限或网络状态。
- 灵感册封面下载失败时保留现有占位表现，不阻断其他灵感册加载。

## 验证

- 对修改后的 JavaScript 运行 `node --check`。
- 运行项目 `npm run lint`。
- 检查视频、图片、文档、组合四类详情渲染条件互斥且完整。
- 检查灵感册有数据和空数据时，三列布局均不溢出。
