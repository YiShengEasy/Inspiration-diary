# 小程序 P2 按需加载与返回保活设计

## 目标

小程序首页不再请求整周最多 200 条完整卡片；日详情、灵感册、搜索和收藏按页加载。打开卡片详情再返回时保留已有列表、滚动位置和筛选条件，不进入全屏加载或清空后重建。

## 服务端

新增 `GET /api/db/weeks/:weekId/summary`，只返回每个 `dayIndex` 的卡片数量与最新 3 条预览卡，以及整周卡片、Markdown 和标签计数。预览仍使用现有 `mapCardRows()` 媒体字段，但最多返回 18 条。

统一 `/api/db/cards` 的分页行为：`weekId=all` 和指定周都返回 `{ cards, total, page, pageSize, totalPages }`，增加可选 `dayIndex`。指定周不再绕过分页一次返回全部卡片。

灵感册继续复用现有分页接口，不新增重复路由。

## 页面加载

- 灵感首页：请求周摘要和灵感册列表，不保存整周完整卡片数组。
- 日详情：每页 20 条，触底追加；已有数据加载下一页时不显示全屏状态。
- 灵感册：每页 20 条，内容滚动区触底追加；切换册子才清空旧册内容。
- 搜索：每页 20 条，输入停止 300ms 后重置搜索；请求序号保证旧响应不能覆盖新关键词。
- 收藏：首屏 12 条，页面触底每次追加 12 条。

所有追加操作以卡片 ID 去重，避免重试或数据变化造成重复项。

## 返回保活

灵感页、“我的”和灵感册首次 `onShow` 使用全屏加载。后续 `onShow` 保留当前数据并静默请求第一页；响应成功后替换首屏数据，失败时保留旧数据并只显示轻提示。详情页返回不会清空数组，也不会切换到全屏 loading。

日详情和搜索没有返回时强制刷新逻辑，微信页面栈会自然保留其数据和滚动状态。

## 错误处理

首次请求失败显示现有错误状态；下一页失败保留当前内容并提示“加载失败”；搜索过期响应直接丢弃。没有下一页时不再请求。

## 验证

验证周摘要最多每天下发 3 条预览；周卡片分页和 `dayIndex` 过滤返回正确总数；各页面请求规格分别为 20/20/20/12；搜索防抖和过期响应保护存在；详情返回路径不会执行清空数组或全屏 loading。运行 API smoke、小程序语法、TypeScript 和生产构建。
