# 标准标签体系与 AI 标签治理设计

**状态：** 已确认，交互原型阶段
**日期：** 2026-07-15
**适用范围：** Inspiration Diary Web、Express API、PostgreSQL、图片／视频／知识文档分析

## 1. 背景

当前标签库只有“分组 → 标签文本”两层。标签在进入 AI 提示词前会被压平成普通字符串，知识节点也只保存 `TEXT[]`。这使系统无法区分“低饱和属于色彩”“玻璃属于材质”，也无法处理同义词、层级相似度、标签来源、置信度和版本。

现有 AI 分析固定生成五个标签，容易连续生成多个近义风格词，却漏掉主题、色彩、材质、构图等分面。候选关系使用字符串精确匹配，高频泛化标签因此产生大量质量较低的关联。

本次设计将标签升级为版本化、可治理的分面体系，并统一图片、视频和文档的 AI 标签生成流程。AI 可以提出建议和积累候选，但不能自动修改系统词库或建立正式知识关系。

## 2. 已确认的关键决策

1. 采用“标准标签表＋分面体系＋用户扩展”，不继续扩展两层 JSON。
2. 系统默认词库只读并版本化；用户通过覆盖设置和私有扩展使用它。
3. 用户可以在系统分类下增加私有标准标签，也可以创建自己的标签包、分面和分类。
4. 用户新词默认私有。重复出现的概念进入候选池，由管理员审核后才能晋升为系统标签。
5. AI 高置信度且命中标准词库的标签可自动附加，但状态为 `ai_unconfirmed`；中等置信度进入待确认；未命中词库只进入候选池。
6. AI 关系建议继续由用户手动触发，确认后才写入正式知识关系。
7. UI 采用“治理收件箱＋三栏标签库”：默认处理 AI 待确认和候选词，标签库页负责完整词库维护。

## 3. 标签信息架构

标签采用固定语义、有限深度：

```text
标签包 → 分面 → 分类（0～2 层）→ 标准标签
```

示例：

```text
图片视觉 → 色彩 → 饱和度 → 低饱和
图片视觉 → 材质 → 透明材质 → 玻璃
视频内容 → 镜头语言 → 运镜 → 推镜头
知识文档 → 知识形式 → 方法类 → 操作指南
```

最多展示五层。只有末级标准标签能够附加到知识节点；“色彩”“风格”等分类节点不能直接使用，避免宽泛分类污染搜索和关系评分。

系统首批标签包：

- 通用核心：主题、主体、情绪、风格、场景、用途、受众。
- 图片视觉：色彩、光线、构图、视角、材质、纹理、视觉媒介。
- 视频内容：镜头、运镜、主体运动、剪辑、转场、节奏、音频、叙事。
- 知识文档：领域、文档类型、知识形式、用途、证据类型、深度、可执行性。
- 我的扩展：用户私有分面、分类和标准标签。

上传时间、地点、设备、文件格式、尺寸和时长是结构化元数据，不进入标签体系。引用、支持、对照、衍生等语义是知识关系，不作为标签保存。

## 4. 数据模型

### 4.1 标签定义

新增：

```text
tag_packs
tag_facets
tag_terms
tag_aliases
tag_term_ancestors
user_tag_settings
```

`tag_terms` 同时容纳分类节点和标准标签，通过 `parent_id` 形成有限层级。主要字段：

```text
id                 UUID primary key
facet_id           UUID not null
parent_id          UUID nullable
owner_user_id      UUID nullable
node_type          category | term
code               TEXT not null
label              TEXT not null
description        TEXT
applicable_media   TEXT[]
default_weight     NUMERIC
status             active | deprecated
replaced_by_id     UUID nullable
taxonomy_version   INTEGER not null
created_at         BIGINT not null
updated_at         BIGINT not null
```

系统标签的 `owner_user_id` 为空；用户扩展带所属用户。系统标签不能被普通用户修改或删除，用户只能隐藏、调整个人偏好权重或增加私有标签。

`tag_term_ancestors` 保存祖先、后代和距离，避免候选关系查询实时递归标签树。

### 4.2 标签使用与治理

新增：

```text
knowledge_node_tags
knowledge_tag_suggestions
tag_candidates
tag_candidate_occurrences
tag_taxonomy_audit_log
```

`knowledge_node_tags` 记录：

```text
user_id
node_id
term_id
source             manual | ai | import | migration
review_state       confirmed | ai_unconfirmed
confidence
evidence
created_at
reviewed_at
```

所有知识、标签使用和用户设置表都带 `user_id`，并通过复合外键阻止跨租户关联。

迁移期间保留 `knowledge_nodes.tags TEXT[]`，作为旧页面和接口的兼容投影。统一标签服务在同一事务内维护标准关系和字符串投影；所有消费者完成切换后再评估删除旧字段。

## 5. AI 标签生成管线

服务端按请求动态组装标签上下文：

```text
识别媒体类型
→ 通用标签包
→ 图片／视频／文档专用标签包
→ 当前目录或灵感册相关标签
→ 用户高频、高接受率标签
→ 按分面发送给 AI
→ 校验、归一和分流结果
```

单次最多提供约 80 个标准标签：通用 16 个、媒体专用 40 个、当前上下文 16 个、个人偏好 8 个。每个候选都携带 `term_id`、分面和标准名称。AI 只能在 `matchedTags` 中返回提供过的 ID，其他概念必须进入 `unmatchedConcepts`。

图片、视频和文档使用独立的媒体模板，但共享标签上下文和输出结构：

```json
{
  "matchedTags": [
    {
      "termId": "color.saturation.low",
      "label": "低饱和",
      "facet": "色彩",
      "confidence": 0.91,
      "evidence": "画面整体灰蓝且颜色对比弱"
    }
  ],
  "unmatchedConcepts": [
    {
      "label": "银长直 JK 少女",
      "suggestedFacet": "主体",
      "confidence": 0.84
    }
  ]
}
```

不再固定五个标签。每次输出 4～12 个，并限制单一分面数量，优先覆盖跨分面的有效特征。

初始阈值：

- `confidence >= 0.82`：自动附加，状态 `ai_unconfirmed`。
- `0.55～0.81`：进入待确认区。
- `< 0.55`：丢弃。
- 未命中标准词库：进入候选池，不附加、不自动创建标签。

服务端必须拒绝未知 ID、错误媒体标签、同分面重复近义标签和超过数量限制的结果。地点默认不发送给 AI。

## 6. 标签自我进化

自我进化只能影响候选与排序，不能直接修改系统词库：

1. 未命中新概念按“规范化名称＋建议分面＋媒体类型”聚合。
2. 统计不同节点出现数、人工接受、拒绝和最近出现时间。
3. 系统提出父级、别名和可能重复标签。
4. 管理员选择晋升、合并别名、继续观察或忽略。
5. 晋升后批量回填历史候选和已接受的自由标签。
6. 用户反馈只调整其个人候选排序，且权重变化受上下限约束。

管理员默认只看到候选名称和汇总统计，不展示用户原始知识内容。所有晋升、合并、弃用和替换操作写入版本化审计日志。

## 7. 知识关系评分

标签相似度改为层级与稀有度结合：

| 标签关系 | 基础强度 |
|---|---:|
| 相同标准标签 | 1.00 |
| 同一分类下的兄弟标签 | 0.45 |
| 只共享上级分类 | 0.15 |
| 只有相同分面 | 0，不单独形成关联 |

附加规则：

- 高频泛化标签使用 IDF 降权。
- 每个分面设置贡献上限，近义标签不能重复累计。
- 通常至少跨两个分面匹配，或命中一个稀有的具体标签。
- `ai_unconfirmed` 标签暂按 0.7 权重计算。
- 同目录、同灵感册和时间接近只作为辅助信号。
- 标签相似度只生成候选关系，不能自动创建正式知识关系。

候选召回先利用 `(user_id, term_id, node_id)` 索引获取有限节点，再计算层级和 IDF；不构造知识节点、标签、目录与关系的全库大联表。

## 8. UI 与交互原型

顶部包含四个页签：

```text
标签库 | AI 待确认 | 候选词 | 变更记录
```

默认进入“AI 待确认”，形成治理收件箱。用户可以逐条确认、忽略或确认当前页，右侧显示标签依据和未命中新词入口。

“标签库”采用三栏资源管理结构：

```text
标签包和层级树 | 当前分类标准标签 | 标签详情与使用情况
```

系统标签只读；用户可以创建私有标签、复制标准 ID、查看别名、适用媒体、AI 采纳率和待确认使用。

“候选词”展示出现次数、人工接受率、建议父级和可能别名。晋升成功后可以直接跳转到标签库中的新标准标签。

“变更记录”展示晋升、合并、停用、替换和人工确认的审计时间线。

交互原型位于 `prototypes/tag-taxonomy-workbench/`，不接入生产 API，不修改现有业务页面。

## 10. 错误处理

- AI 返回未知标签 ID：拒绝该项并记录模型输出诊断。
- 标签媒体范围不匹配：进入待确认，不自动附加。
- 同级标准名称或别名冲突：返回明确的 409，并提供可能合并目标。
- 晋升过程中回填失败：整个事务回滚，候选状态保持不变。
- 系统词库版本升级冲突：保留旧标签的 `replaced_by_id`，不删除历史使用。
- 缩略图或内容预览失败：只降级该预览，不阻断标签审核。

## 11. 迁移顺序

1. 建立标签定义、祖先路径、标签使用和审计表。
2. 导入版本化系统默认词库和用户现有自定义分组。
3. 对现有字符串标签执行标准名称、别名和规范化匹配；无法匹配的保留为私有候选。
4. 新上传内容切换到结构化 AI 标签管线，同时双写兼容字符串字段。
5. 历史知识节点分批回填标准标签关系，记录游标和计数，可重复执行。
6. 候选关系评分切换到标准标签层级和 IDF。
7. 发布治理工作台，最后停止旧标签库写入。

迁移不得自动删除旧标签或自动建立知识关系。

## 12. 测试与验收

- 标签树深度、父级合法性、同级名称和别名冲突。
- 系统标签只读、用户私有标签隔离、跨租户引用阻止。
- AI 标签 ID 白名单、媒体范围、分面配额、阈值和未知概念分流。
- 高置信度自动附加保持 `ai_unconfirmed`，人工确认后状态正确。
- 候选聚合、晋升、别名合并、历史回填和审计日志事务一致。
- 精确标签、兄弟标签、泛化父级、IDF 和未确认权重评分。
- 旧 `TEXT[]` 与新关系表双写一致，回填任务幂等。
- 10 万知识节点和百万级标签使用下，标签列表、候选召回和局部关系查询保持有界。
- 原型的页签、树选择、搜索、AI 确认、候选晋升、新建私有标签和审计视图可操作。

## 13. 非目标

- 不在本阶段引入图数据库、Elasticsearch 或新的常驻服务。
- 不允许 AI 自动晋升系统标签。
- 不允许 AI 自动创建正式知识关系。
- 不把结构化文件元数据或知识关系混入标签体系。
- 交互原型不接入真实数据库和 AI 接口。
