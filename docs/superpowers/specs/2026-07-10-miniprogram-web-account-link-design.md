# 小程序关联 Web 账号设计

## 目标

微信登录只负责确认微信身份。尚未关联用户的微信身份必须继续完成以下任一流程，才能进入已注册状态并访问 Web 端同一份灵感数据：

- 使用 Web 账号和密码关联已有账号。
- 注册一个新的 Web 账号。

## 页面流程

现有“完成账号注册”页面改为“关联账号”页面，提供“关联已有账号”和“注册新账号”两个模式，默认选择关联已有账号。

两个模式都使用手机号或邮箱和密码。关联模式明确提示输入 Web 端登录信息；注册模式保留微信手机号授权回填，并提示注册后可在 Web 端使用同一账号密码登录。

成功后统一将接口返回的 `accountState` 和 `user` 写入小程序全局状态，再返回“我的”。“我的”页面的 `onShow` 会继续从后端复核当前 session。

## 关联接口

新增 `POST /api/auth/link-existing-account`，请求必须携带当前 `miniToken`，请求体为：

```json
{
  "identifier": "Web 端手机号或邮箱",
  "password": "Web 端密码"
}
```

服务端按 Web 登录的相同规则查找用户并校验密码。验证成功后，在同一数据库事务中：

1. 锁定当前 mini session 对应的微信 identity。
2. 将 `wechat_identities.user_id` 更新为 Web 用户 ID。
3. 将当前 `mini_program_sessions.user_id` 更新为同一用户 ID。
4. 返回 `accountState: "registered"` 和 Web 用户信息。

如果微信 identity 已关联同一账号，接口直接返回成功；如果已关联其他账号，返回冲突错误，不允许静默覆盖。账号不存在或密码错误统一返回“账号或密码不正确”，避免泄露账号是否存在。

## 注册接口

现有 `POST /api/auth/complete-registration` 保持创建新账号的职责。账号已存在时提示用户切换到“关联已有账号”，不自动把注册请求解释为登录请求。

## 验证

- 创建一个 Web 账号。
- 使用新的 Mock 微信身份登录，确认状态为未注册。
- 用 Web 账号密码调用关联接口。
- 使用原 mini token 查询账号状态，确认返回 `registered` 且用户 ID 与 Web 账号一致。
- 使用错误密码关联时确认返回 401，且微信身份保持未关联。
- 保留现有注册新账号、手机号授权和调试密码登录冒烟链路。
- 运行小程序 JavaScript 语法检查、TypeScript lint 和生产构建。
