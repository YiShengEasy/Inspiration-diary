# Web P3 媒体流量优化设计

## 目标

在不改变现有上传、下载、鉴权和小程序接口默认行为的前提下，减少 Web 列表与详情页的媒体初始化请求，并降低 API 与静态资源重复传输。

## 方案

1. 列表继续使用缩略图，统一启用浏览器原生懒加载和异步解码。
2. 图片详情先显示列表已有缩略图，后台加载 `detail-1280`，加载成功后原位替换；原图仅由下载操作获取。
3. 独立视频、绑定视频和组合生成记录初始只渲染海报按钮。用户点击后才创建 `<video>`；组件卸载或资源切换时暂停播放、移除 `src` 并调用 `load()`。
4. Web 列表请求增加 `view=list`，服务端仅在该模式省略绑定图片数组，默认 API 响应保持兼容。
5. Express 对超过 1 KB 的可压缩响应启用压缩。生产环境 `index.html` 使用 `no-cache`，Vite 带指纹资源使用一年 `immutable`，其他静态资源缓存一天。

## 兼容与回滚

- `view=list` 是显式可选参数，小程序和旧调用方不受影响。
- OSS 直连、媒体代理回滚开关和原图下载路径保持不变。
- 海报缺失时仍显示可点击的播放占位，不预取视频字节。

## 验收

- TypeScript 检查和生产构建通过。
- 详情页初始 DOM 中不同时创建多个视频播放器。
- 压缩响应包含 `Content-Encoding`，HTML 与带指纹资源的缓存头符合设计。
- 登录、组合资源、媒体交付及小程序分页烟测无回归。
