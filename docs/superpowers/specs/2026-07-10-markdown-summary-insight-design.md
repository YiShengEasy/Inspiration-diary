# Web 端 Markdown 摘要与感悟自动入库设计

## 目标

Web 端上传 Markdown 文档时，在现有 AI 摘要和五个标签之外，自动生成一段独立的内容分析，并存入卡片的“感悟 / 备注”字段。用户仍可在卡片详情中编辑和覆盖这段自动生成内容。

## 范围

- 仅调整 Web 端文档上传链路和服务端 Markdown 分析接口。
- Markdown、Markdown MIME 类型以及当前统一进入该链路的 TXT、PDF、DOCX 文档均沿用相同行为。
- 不修改图片分析、小程序、每周便笺和其他卡片类型。
- 保留现有“一次生成五个标签”的限制。

## 接口设计

`POST /api/summarize-md` 继续使用一次模型调用，响应从：

```json
{
  "summary": "卡片预览摘要",
  "terms": ["标签1", "标签2", "标签3", "标签4", "标签5"]
}
```

扩展为：

```json
{
  "summary": "卡片预览摘要",
  "terms": ["标签1", "标签2", "标签3", "标签4", "标签5"],
  "insightNote": "核心观点、可借鉴启发和行动建议"
}
```

服务端提示词明确区分：

- `summary`：客观概括文档内容，控制在两到三句话，用于卡片预览。
- `terms`：严格五个内容标签，沿用自定义标签库和灵感册提示。
- `insightNote`：面向使用者的内容分析，提炼核心观点、启发和可执行建议，不重复摘要，不虚构文档没有的信息。

所有模型提供商分支共用同一提示词、解析和标准化逻辑。Gemini 的结构化响应定义同步加入 `insightNote`。

## 数据流

1. 用户上传文档，Web 端提取正文。
2. Web 端调用 `/api/summarize-md`。
3. 服务端一次生成 `summary`、五个 `terms` 和 `insightNote`。
4. Web 端创建卡片时分别写入 `mdSummary`、`terms` 和 `insightNote`。
5. 现有 `saveCard` 将 `insightNote` 保存到 `cards.insight_note`。
6. 用户打开详情页时，在“感悟 / 备注”中看到自动分析，并可继续编辑保存。

## 降级与错误处理

- 模型未配置、调用失败或返回格式错误时，文档上传不能失败。
- 服务端继续生成本地 `summary` 和默认标签，并额外生成简短的本地 `insightNote`。
- 本地感悟从清洗后的正文片段生成，使用明确的分析引导语，不伪装成深度 AI 推理。
- 如果旧服务端未返回 `insightNote`，Web 端使用同样的本地降级内容，保证兼容滚动部署。
- 空白文档继续按现有规则拒绝。

## 前端行为

- 不新增上传步骤、弹窗或配置项。
- 上传等待时间只包含现有的一次 AI 请求。
- 新卡片创建完成后，“感悟 / 备注”直接显示自动分析。
- 用户后续编辑的备注不触发自动重新生成，也不会被后台覆盖。

## 验证

- 服务端类型检查和前端构建通过。
- 验证正常模型响应会把三个字段分别保存到正确位置。
- 验证模型失败时文档仍能上传，且摘要、标签和备注都有降级值。
- 验证标签最多五个，自动备注可在详情页编辑并保存。
- 验证图片上传和已有卡片读取行为不受影响。
