# 灵感册智能建议收录设计

## 背景

Web 端已经支持创建灵感册，并在卡片详情中手动把图片或 Markdown 灵感收录到一个或多个灵感册。图片上传后会生成视觉标签，Markdown 上传后会生成摘要和标签。这些标签和摘要可以用来判断一条新灵感是否适合某本灵感册。

这次新增“智能建议收录”能力：用户在灵感册页面顶部开启对应开关后，新上传的图片或 Markdown 在生成标签/摘要后，会根据灵感册名称和描述做匹配。如果匹配到合适的灵感册，系统弹出确认提示；用户确认后，卡片才会加入该灵感册。

## 范围

### 包含

- 在 Web 端灵感册页面顶部新增智能收录区域。
- 提供两个独立开关：
  - 图片建议入册
  - MD 建议入册
- 开关状态保存到现有用户 settings 中。
- 图片 AI 标签生成成功后，如果图片开关开启，触发灵感册建议匹配。
- Markdown 摘要/标签生成成功后，如果 MD 开关开启，触发灵感册建议匹配。
- 匹配依据使用卡片标签、Markdown 文件名/摘要、灵感册名称和描述。
- 命中后弹出确认弹窗。
- 用户点击确认后，调用现有灵感册收录接口把卡片加入推荐灵感册。
- 用户拒绝或关闭弹窗时，不自动加入。

### 不包含

- 不新增数据库表。
- 不新增后端 AI 匹配接口。
- 不在未确认时自动加入灵感册。
- 不对旧卡片批量回扫。
- 不一次推荐多本灵感册。
- 不改变现有手动“收录到灵感册”入口。
- 不扫描灵感册中已有卡片作为匹配输入。

## 用户体验

### 开关位置

开关放在“灵感册”页面顶部，作为灵感册模块内部的智能建议偏好。它不放在全局设置里，也不放在每日上传格子里。

页面顶部区域展示：

- 标题：智能建议收录
- 简短说明：上传后根据标签和灵感册名称/描述推荐入册
- `图片建议入册` 开关
- `MD 建议入册` 开关

两个开关互相独立：

- 只开图片：只有图片卡片会触发建议。
- 只开 MD：只有 Markdown 卡片会触发建议。
- 两个都开：图片和 Markdown 都会触发建议。
- 两个都关：不做匹配，也不弹窗。

### 确认弹窗

当匹配到灵感册后，弹出轻量确认弹窗：

```text
这条灵感可能适合加入《中世纪家具》
```

弹窗展示：

- 推荐灵感册名称。
- 灵感册描述。
- 命中的标签或摘要片段。
- 操作按钮：
  - 加入灵感册
  - 暂不加入

用户点击“加入灵感册”后，系统执行收录；用户点击“暂不加入”或关闭弹窗，本次不收录。

## 数据流

### 图片卡片

1. 用户上传图片。
2. 系统先保存图片并创建图片卡片。
3. AI 标签分析完成后，调用现有标签更新逻辑。
4. 标签更新成功后，如果 `图片建议入册` 开启，触发灵感册匹配。
5. 匹配成功则弹出确认弹窗。
6. 用户确认后调用 `setCardBookMembership(cardId, bookId, true)`。

图片标签分析失败时，不触发智能建议。图片卡片仍保留兜底标签和现有上传行为。

### Markdown 卡片

1. 用户上传 Markdown。
2. 系统读取文本。
3. AI 摘要/标签生成完成，或摘要服务失败时使用兜底摘要/标签。
4. 保存 `type: "md"` 卡片。
5. 如果 `MD 建议入册` 开启，触发灵感册匹配。
6. 匹配成功则弹出确认弹窗。
7. 用户确认后调用 `setCardBookMembership(cardId, bookId, true)`。

空 Markdown 不建卡，也不触发智能建议。

## 匹配设计

### 输入

卡片侧：

- `terms`
- `type`
- `mdName`
- `mdSummary`

灵感册侧：

- `title`
- `description`

不使用灵感册里已有卡片内容，避免匹配过慢，也避免提示词或本地匹配输入过大。

### 算法

MVP 使用前端规则匹配，不新增后端 AI 匹配接口。

匹配步骤：

1. 规范化文本：转小写、去掉多余符号、按空白和常见标点拆分。
2. 生成卡片关键词集合：
   - 图片：主要使用 `terms`。
   - Markdown：使用 `terms`、`mdName`、`mdSummary`。
3. 生成灵感册文本集合：使用 `title` 和 `description`。
4. 计算匹配分：
   - 完整标签命中灵感册标题或描述，得高分。
   - 灵感册标题或描述命中标签，得高分。
   - 中文子串或短语重合，得中分。
   - 普通分词重合，得低分。
5. 只取最高分且超过阈值的一本灵感册。

如果没有超过阈值的候选，不弹窗。如果多本分数相近，也只推荐最高分的一本，避免打扰。

### 去重

以下情况不弹窗：

- 当前没有灵感册。
- 卡片已经在推荐的灵感册中。
- 同一卡片同一本灵感册已经被用户拒绝过。
- 当前已有一个智能建议弹窗未处理。

用户拒绝后，本次会话内不再对同一卡片同一本灵感册重复弹窗。

## 设置保存

开关状态保存到现有 settings 机制中。建议使用两个 key：

```text
smart_book_suggest_images
smart_book_suggest_markdown
```

值使用字符串：

```text
true
false
```

页面加载时读取 settings；用户切换开关后立即更新本地状态，并异步保存。保存失败时，前端开关可以继续临时生效，但需要给出轻量提示，说明设置同步失败。

## 错误处理

- 加载灵感册失败：不触发匹配，并保留正常上传流程。
- 加载 settings 失败：默认两个开关关闭。
- 保存 settings 失败：显示轻量提示，但不阻止本次页面内开关生效。
- 执行收录失败：弹窗内显示错误，用户可以稍后用现有手动收录入口处理。
- 匹配算法异常：吞掉该次建议，不影响上传、标签和手动收录。

## 组件边界

### `InspirationBooksView`

负责展示灵感册页面顶部的两个开关，并保存用户偏好。

### `App`

负责在图片标签更新成功、Markdown 卡片创建成功后触发智能建议匹配。`App` 已经拥有上传流程、卡片上下文和灵感册刷新 token，适合作为建议协调层。

### `booksClient`

继续复用现有方法：

- `loadBooks`
- `loadCardBookMembership`
- `setCardBookMembership`

不新增后端 API。

### 新的前端工具函数

新增一个纯前端 helper：`src/lib/bookSuggestion.ts`，负责：

- 规范化文本。
- 计算卡片和灵感册的匹配分。
- 返回最高分候选。

该 helper 不依赖 React，不发起网络请求，便于单独理解和后续测试。

## 验证计划

- `npm run lint` 通过。
- 进入灵感册页面，可以看到两个独立开关。
- 打开图片建议、关闭 MD 建议后，图片上传并生成标签后可能弹建议，MD 不弹。
- 打开 MD 建议、关闭图片建议后，MD 上传并生成标签后可能弹建议，图片不弹。
- 两个开关都关闭时，不做匹配、不弹窗。
- 有匹配时，点击“加入灵感册”后，卡片加入对应灵感册。
- 点击“暂不加入”后，同一卡片同一本灵感册不重复弹。
- 卡片已经在推荐灵感册中时不弹。
- 没有灵感册时不弹。
- 灵感册加载失败时，不影响上传和手动收录。

## 实施顺序

1. 新增纯前端灵感册匹配 helper。
2. 在灵感册页面顶部增加两个开关。
3. 用现有 settings 机制保存开关状态。
4. 在 `App` 中加载开关状态和灵感册列表。
5. 在图片标签更新成功后触发图片建议匹配。
6. 在 Markdown 卡片创建成功后触发 MD 建议匹配。
7. 新增确认弹窗，确认后调用现有收录接口。
8. 补齐去重、失败提示和刷新逻辑。
9. 运行类型检查并手动验证图片、MD、拒绝、已收录等场景。
